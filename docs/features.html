calrs v2 Documentation

Features in v2

This is the feature map for v2, including capabilities carried forward from v1. It describes implemented behavior in the v2 source, not proposed features. For changes between individual builds, see the changelog.

Calendars

CapabilityWhat you can do
CalDAVConnect Nextcloud, BlueMind, Fastmail, iCloud, SOGo, Zimbra, Radicale, Baikal and other CalDAV servers; discover calendars, sync changes and write bookings back. CalDAV
Google CalendarConnect with OAuth2, block out-of-office events, write bookings and create host-owned Google Meet links. Google Calendar
Microsoft 365 / Outlook.comConnect with delegated OAuth2 through Microsoft Graph; select calendars and a writable destination. Microsoft Calendar
On-premises ExchangeConnect individual mailboxes through EWS, or provision managed calendars with a service account and trusted mailbox addresses. Exchange, EWS impersonation
Calendar selectionChoose which calendars a source syncs, which synced calendars block each event type, and which calendar receives each host’s confirmed bookings. Selection and write-back
Sync and recoveryRefresh on demand and in the background, force a full resync, inspect sync errors and write-back retries, and receive persistent-failure alerts. Sync failures, background sync
Recurring eventsAccount for recurrence rules, added/removed dates and moved instances; conservatively block unsupported rules. Recurring events

Availability and booking rules

CapabilityWhat you can do
Working hoursSet default personal hours and multiple windows per day, then give each event type its own schedule and timezone. Availability
Time off and exceptionsTake time off across all meetings you host, or override one event type’s hours on a date. Time off, date overrides
Timing controlsSet duration, slot interval, before/after buffers, minimum booking notice and guest cancel/reschedule notice. Event types, notice policy
Booking windowsSet a rolling horizon or an inclusive fixed date range; expired event types leave public listings. Booking horizon, date range
Frequency limitsCap bookings per day, week, month or year, optionally per round-robin member; show only the earliest remaining slot per day. Booking limits
ApprovalsRequire confirmation, hold pending slots, expire unanswered requests and remind the host to answer. Confirmation mode
Conflict checksRe-check availability when booking and approving; account for busy calendars, bookings, time off, member hours and required resources. Conflict detection
TroubleshootingSee why a time is unavailable, including conservative blocking of unsupported recurrence rules. Dashboard

Meetings and sharing

CapabilityWhat you can do
Personal and team meetingsBook one host, assign an available team member by priority and workload, or require all eligible members. Teams
Dynamic groupsCombine usernames in a link such as /u/alice+bob/intro for an ad-hoc collective meeting. Dynamic group links
WatchersNotify a support team and let the first person claim a booking; the confirmed claim blocks their time. Booking watchers
Visibility and invitationsPublish meetings, let colleagues distribute internal meetings, or send private invitations; use expiry, usage limits and bulk invitations. Event types
Directory and favoritesSearch meetings you can share, copy public links, generate internal invites and keep favorites on your overview. Booking directory
Public pagesAdd profile facts, Markdown descriptions, meeting sections and ordering; show meeting duration, location and confirmation requirements. Sections and order
EmbedsAdd an inline picker, floating booking button or click-triggered modal; set layout, theme, branding, timezone and clock format. Embedding
Shared resourcesReserve rooms, demo labs or other resources from ICS availability feeds, with optional CalDAV write-back and team allowlists. Resources

Guest experience and notifications

CapabilityWhat you can do
Slot pickerOffer month, week and column views, a timezone picker, 12/24-hour clocks and a configurable first weekday. Calendar views
Booking questionsAsk short/long text, single/multiple choice and checkbox questions; record consent and retain the question as answered. Booking questions
Attendees and notesAllow additional guests, choose whether guest notes are optional/required/hidden, and keep separate host-only notes. Booking flow, host notes
Changes after bookingApprove, decline, cancel, reschedule or ask a guest to choose a new time; keep calendar copies and attendees updated. Booking flow
EmailSend translated HTML/plain-text messages, reminders and calendar invitations; use the host’s display name and Reply-To, plus an optional guest footer. Email notifications, SMTP
SMSSend guest confirmations, cancellations, reschedules and reminders through Twilio, GatewayAPI, seven.io or a webhook gateway, with a daily segment limit. SMS
Meeting locationsUse static video links, phone, in-person or custom locations, generated Jitsi rooms, Google Meet or a meeting-provider webhook. Locations
Localization and appearanceUse ten languages plus formal German, light/dark modes, preset/custom themes, company logos for each mode and a favicon. Profile settings, branding

Administration and integrations

CapabilityWhat you can do
IdentityUse local accounts with optional/required TOTP and recovery codes, or OIDC SSO with group sync. Authentication, Authentik
AdministrationManage users, groups and instance policies, impersonate users for troubleshooting, inspect booking and calendar health. Admin dashboard
WebhooksDeliver signed booking lifecycle events with retries and stable delivery IDs. Webhooks
REST API and OpenAPIUse scoped OAuth or personal access tokens for event types, slots and booking operations, including optional question answers; use /api/docs for the interactive reference. REST API
MCPAuthorize an OAuth-capable Streamable HTTP client to list event types, create invites and read cached busy intervals. MCP
Operator CLIManage sources, sync, event types, bookings, users, time off and configuration; import calendar OAuth credentials and export non-secret configuration. CLI reference
Self-hostingRun a container or systemd service, keep SQLite and credential-key backups, configure trusted proxies and private calendar hosts. Deployment, security

These integrations have different scopes. MCP does not create bookings; use the REST API for supported booking operations. Calendar OAuth connects calendars; OIDC configures sign-in. A meeting-provider webhook returns a video URL; an outgoing booking webhook reports a lifecycle event.
